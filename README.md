## 🎯 Зачем это нужно

Большинство IPTV-плееров делаются для энтузиастов: десятки кнопок, непонятные настройки, тяжёлый интерфейс. Этот проект родился из двух конкретных задач:

1. **Быть абсолютно понятным взрослому поколению.** Открыл программу, нажал на канал, смотришь. Крупные кнопки, крупный текст на выбор, звёздочка «в избранное» прямо в списке, набор номера канала цифрами как на пульте телевизора, режим «Просто», где спрятано всё редактирование.
2. **Работать на слабом ноутбуке с Windows 7 и нестабильным интернетом.** Все тяжёлые операции вынесены из потока интерфейса, программа сама замечает оборванный или «замерший» эфир и переподключается, а при проблемах показывает простое объяснение вместо технической ошибки.

Плеер построен на движке **LibVLC**, то есть открывает всё, что умеет VLC, но не тащит за собой его интерфейс.

## 🤔 Чем отличается от VLC и Kodi

**Коротко:** как *проигрыватель* эта программа не лучше VLC, потому что внутри у неё тот же движок. Декодирование, поддержка форматов и нагрузка на процессор те же самые. Отличается **оболочка**: она сделана под один конкретный сценарий, «включил и смотрю», для человека, который не хочет разбираться в настройках.

### Почему не просто VLC

VLC умеет открывать M3U-плейлисты, но для повседневного просмотра телевидения он неудобен:

- список каналов спрятан в окне плейлиста, нет избранного и нормального поиска;
- нельзя набрать номер канала цифрами, как на пульте;
- при пропавшей сети VLC нередко замирает на последнем кадре и не переподключается сам;
- интерфейс и настройки рассчитаны на технически подкованного человека;
- управление с телефона возможно, но его нужно настраивать вручную.

### Сравнение

| | Эта программа | VLC | Kodi + PVR IPTV Simple Client |
|---|---|---|---|
| Движок | LibVLC | VLC | собственный на базе FFmpeg |
| Windows 7 | ✅ | ✅ (ветка 3.x) | ⚠️ только старые версии: по сообщениям, Kodi 21 отказался от Windows 7 |
| Нагрузка на слабый ноутбук | низкая | низкая | выше |
| Избранное и «Недавние» | ✅ | ❌ | ✅ |
| Набор номера канала цифрами | ✅ | ❌ | ✅ |
| Автопереподключение при обрыве и замирании | ✅ | ❌ (замирание на кадре обычно приходится лечить вручную) | зависит от настроек |
| Пульт с телефона «из коробки» | ✅ | настраивается вручную | через отдельные приложения |
| Режим «Просто» и крупный текст | ✅ | ❌ | частично, через темы |
| Телепрограмма (EPG) | ❌ (в планах) | ❌ | ✅ |
| Запись эфира | ❌ | ✅ | ✅ |
| Сложность настройки | минимальная | средняя | высокая |

Сравнение составлено по состоянию на момент написания. Версии и возможности программ меняются, поэтому перед выбором проверьте актуальную информацию на их сайтах.

### Кому подойдёт эта программа

- у вас **слабый ноутбук или компьютер с Windows 7**, а современные программы на нём не запускаются или тормозят;
- вы настраиваете телевидение **для родителей, бабушек и дедушек**, и им нужно как можно меньше кнопок;
- **нестабильный интернет**, и важно, чтобы программа сама поднимала оборвавшийся эфир;
- вам достаточно смотреть каналы из готового плейлиста.

### Когда лучше взять что-то другое

- **Нужна телепрограмма, запись или архив передач.** Берите Kodi с PVR IPTV Simple Client или специализированный IPTV-плеер.
- **Компьютер современный и мощный.** Тогда возможностей Kodi или другого полноценного медиацентра будет больше, чем здесь.
- **Нужен интерфейс для телевизора с пультом.** Дешёвая Android TV-приставка (или Smart TV) с IPTV-приложением часто удобнее ноутбука: пульт, крупные кнопки, ничего не надо ставить на Windows. Если цель именно «чтобы родителям было удобно» и менять оборудование можно, это стоит рассмотреть в первую очередь.
- **Нужна поддержка и гарантии.** Это хобби-проект без обязательств (см. заметку в начале).

Программа не пытается конкурировать с Kodi по числу функций. Её задача проще: быть понятной и не падать на слабом железе.

## ✨ Возможности

### Просмотр

- Воспроизведение любых потоков, которые понимает LibVLC: HTTP/HTTPS (в том числе HLS), UDP, RTSP, RTP и другие.
- Переключение каналов стрелками, кнопками, набором номера цифрами и возвратом на предыдущий канал (`Backspace`).
- Небольшая задержка при быстром перебирании каналов: при пролистывании стрелками поднимается только последний выбранный канал, а не десяток потоков подряд.
- Полный экран (клавиша `F`/`F11` или двойной щелчок по видео) с автоскрытием панели и курсора.
- Смена соотношения сторон: Авто → 16:9 → 4:3.
- Громкость, выключение звука, запоминание уровня между запусками.
- Возобновление на последнем просмотренном канале при следующем запуске.

### Список каналов

- Поиск по названию, категории и номеру. Можно вводить несколько слов подряд: запрос `первый hd` найдёт «Первый канал HD». Номер ищется по началу числа.
- Вкладки **Все каналы**, **★ Избранное**, **Недавние** (последние 200 просмотренных).
- Фильтр по категории (`group-title`), сортировка «как в плейлисте» или по алфавиту.
- Звёздочка избранного нажимается прямо в строке списка.
- Виртуализация списка: плейлисты в тысячи каналов не тормозят прокрутку.
- Контекстное меню по правой кнопке.

### Работа с плейлистом

- Загрузка из файла `.m3u` / `.m3u8` или по ссылке `http(s)://`.
- Если по ссылке лежит не плейлист, а прямой поток, он просто запускается.
- Автоопределение кодировки: UTF-8 (с BOM и без), UTF-16, откат на Windows-1251.
- Поддержка `#EXTVLCOPT`, `#EXTHTTP` и формата `url|User-Agent=...&Referer=...`: без них часть каналов вообще не открывается.
- Редактирование: переименование, смена номера и категории, изменение адреса, перемещение вверх/вниз, удаление канала или целой категории.
- Экспорт плейлиста с сохранением всех атрибутов и опций.
- Рабочий плейлист автоматически сохраняется и восстанавливается при запуске, правки не теряются.

### Устойчивость на слабом железе и плохой сети

- Все блокирующие вызовы LibVLC (остановка, запуск, громкость, формат кадра) выполняются **вне потока интерфейса**. Окно не «замерзает», даже если сервер не отвечает.
- Состояние плеера кэшируется из событий LibVLC, интерфейс не обращается к плееру напрямую.
- **Автопереподключение** при ошибке, обрыве и «замерзшем» кадре, с растущими паузами между попытками.
- **Сторож замершего эфира:** если поток молчит дольше 15 секунд, но VLC не сообщает об ошибке, программа переподключается сама.
- Настраиваемый размер буфера (300–4000 мс).
- Выбор режима аппаратного декодирования (автоматически / DXVA2 / выключено).
- Опциональный повышенный приоритет процесса.
- Включение TLS 1.2 для Windows 7, чтобы `https`-плейлисты вообще загружались.
- Безопасная запись файлов через временный файл: аварийное завершение не оставит обрезанный плейлист.

### Удобство для неопытных пользователей

- Два режима интерфейса: **«Просто»** (только просмотр, поиск, избранное) и **«Профи»** (правка плейлиста, диагностика, расширенные настройки).
- Три размера текста: **Обычный / Крупный / Огромный**. Меняются мгновенно, без перезапуска.
- Понятные сообщения вместо кодов ошибок: «Сервер не отвечает», «Поток замер на последнем кадре», «Подключаюсь к каналу…» с секундомером.
- Встроенная справка по горячим клавишам (`F1`).
- Тёмная тема с высоким контрастом; ни один элемент не «вспыхивает» белым при наведении.

### Дополнительно

- **Пульт с телефона:** управление каналами и громкостью через браузер по домашней сети, защита PIN-кодом.
- **Проверка доступности каналов:** массовая проверка `http/https`-адресов, недоступные каналы притушиваются.
- **Индикатор потока:** скорость приёма, потерянные кадры и состояние буфера прямо поверх видео.

## 💻 Системные требования

| | Минимум | Рекомендуется |
|---|---|---|
| **ОС** | Windows 7 SP1 | Windows 7 SP1 и новее |
| **Разрядность** | 32-бит (x86) или 64-бит | любая |
| **.NET** | .NET Framework 4.7.2 (см. `TargetFramework` в проекте) | .NET Framework 4.8 |
| **Процессор** | двухъядерный, ~2 ГГц | с аппаратным декодированием H.264 в видеокарте |
| **ОЗУ** | 2 ГБ | 4 ГБ |
| **Сеть** | стабильные 5 Мбит/с для SD/HD 720p | 10+ Мбит/с для 1080p |
| **Видео** | видеокарта с DirectX 9 и DXVA2 | — |

**Замечания:**

- Программа использует **LibVLC 3.x**, единственную ветку, которая официально поддерживает Windows 7. Ветка 4.x на Windows 7 не работает.
- Видео **H.265 / HEVC** на слабом ноутбуке времён Windows 7 почти наверняка не потянется: у видеокарты нет его аппаратной поддержки, а процессор не справится. Выбирайте каналы **H.264 720p**, если есть выбор.
- Для Windows 7 нужен **Service Pack 1**, иначе .NET Framework 4.8 не установится.

## 📦 Установка

### Вариант 1. Установщик (рекомендуется)

1. Скачайте `IPTV-Setup.exe` со страницы [Releases](../../releases).
2. Запустите его и нажмите «Далее». Права администратора **не нужны**: программа ставится в папку профиля пользователя (`%LocalAppData%\IPTV Player`).
3. Установщик сам проверит наличие .NET Framework и подскажет, если его нужно доустановить.
4. Запустите программу с рабочего стола или из меню «Пуск».

### Вариант 2. Портативная версия (zip)

1. Скачайте архив `IPTV-portable.zip` со страницы [Releases](../../releases).
2. Распакуйте **целиком** в любую папку, например `C:\IPTV`. Не в `Program Files`: программа хранит настройки рядом с `iptv.exe`, и запись в защищённые папки может не работать.
3. Запустите `iptv.exe`.

> **Одного `iptv.exe` недостаточно.** Ему нужны рядом библиотеки `LibVLCSharp.dll`, `LibVLCSharp.WPF.dll`, `Newtonsoft.Json.dll` и папка `libvlc` (с `libvlc.dll`, `libvlccore.dll` и подпапкой `plugins`). Копируйте папку целиком.

### Установка .NET Framework

Если установщик или программа сообщают об отсутствии .NET:

1. Убедитесь, что на Windows 7 установлен **Service Pack 1**.
2. Скачайте и установите **.NET Framework 4.8** с сайта Microsoft.
3. Перезагрузите компьютер и повторите установку.

## 🚀 Быстрый старт

1. **Запустите программу.** При первом запуске появится экран «Плейлист не загружен».
2. **Загрузите плейлист** одним из способов:
   - нажмите **«Открыть файл»** и выберите `.m3u` / `.m3u8`;
   - либо вставьте **ссылку** на плейлист в поле сверху и нажмите **«Загрузить»** (или `F5`).
3. Программа разберёт плейлист и **сразу запустит первый канал**.
4. Выбирайте каналы в списке слева одним щелчком.
5. Нажмите на **☆** справа в строке канала, чтобы добавить его в избранное.
6. Для набора номера как на пульте телевизора просто нажимайте цифры на клавиатуре (например, `1` `2` `7`) и подождите секунду.

При следующем запуске программа сама вернётся к последнему плейлисту и каналу.

## 📄 Поддерживаемые форматы плейлистов

Поддерживаются файлы `M3U` и `M3U8` (расширенный формат `#EXTM3U`).

### Распознаваемые теги

| Тег / атрибут | Что делает программа |
|---|---|
| `#EXTM3U url-tvg="..."` или `x-tvg-url="..."` | Запоминает ссылку на телепрограмму (EPG) |
| `#EXTINF:-1 ...,Название` | Название берётся по первой запятой **вне кавычек** (запятая внутри `tvg-name` больше не ломает разбор) |
| `group-title` | Категория канала |
| `tvg-id`, `tvg-name`, `tvg-logo` | Сохраняются и записываются обратно при экспорте |
| `catchup`, `catchup-source`, `catchup-days` | Считываются и сохраняются (задел под архив передач) |
| `#EXTGRP:Имя` | Категория действует до следующего объявления, как в спецификации |
| `#EXTVLCOPT:опция` | Передаётся в LibVLC для конкретного канала (`http-user-agent`, `http-referrer` и др.) |
| `#EXTHTTP:{"User-Agent":"...","Referer":"..."}` | Из JSON берутся `User-Agent` и `Referer` |
| `url\|User-Agent=...&Referer=...` | Заголовки в конце адреса (встречается в «народных» плейлистах) |
| Прочие `#…` строки (`#KODIPROP` и т. п.) | Пропускаются |

### Пример

```m3u
#EXTM3U url-tvg="http://example.com/epg.xml.gz"
#EXTINF:-1 tvg-id="ch1" tvg-logo="http://example.com/1.png" group-title="Новости",Первый канал
#EXTVLCOPT:http-user-agent=Mozilla/5.0
#EXTVLCOPT:http-referrer=http://example.com/
http://example.com/stream/1.m3u8
#EXTGRP:Кино
#EXTINF:-1,Кино HD
http://example.com/stream/2.m3u8|User-Agent=VLC/3.0.20
```

### Кодировки

Определяются автоматически: BOM UTF-8 / UTF-16 → строгая проверка на UTF-8 → откат на **Windows-1251** (частый случай для старых русскоязычных плейлистов).

### Что происходит при загрузке по ссылке

1. Скачивание с коротким таймаутом (15 с) и одной повторной попыткой.
2. Если содержимое начинается не с `#EXTM3U` / `#EXTINF`, ссылка считается **прямым потоком** и просто запускается.
3. Разбор большого плейлиста выполняется в фоне, окно не зависает.
4. Если пока шла загрузка вы запросили другой плейлист, устаревший результат отбрасывается.

## 📊 Индикатор потока (диагностика)

Небольшая плашка в правом верхнем углу видео. Включается в **Настройки → «Показывать индикатор потока»** (режим «Профи»).

Пример:

```
↓  2.4 Мбит/с  ·  кадров потеряно:    0  ·  буфер 100% ·  подвисаний: 0
```

| Показатель | Что означает | Что делать |
|---|---|---|
| **↓ Мбит/с** | Реальная скорость приёма потока за последнюю секунду | Если скорость упала до нуля или скачет — сеть или сам источник |
| **кадров потеряно** | Сколько кадров декодер не успел показать | Если растёт — не справляется процессор или видеокарта: смените режим декодирования или выберите поток попроще |
| **буфер N%** | Заполнение запаса данных. Вне подзагрузки это 100% | Если проценты падают посреди эфира — сеть не успевает, увеличьте буфер |
| **подвисаний** | Сколько раз эфир останавливался на подгрузку с момента включения канала | Если растёт вместе с падением скорости — сеть или источник, попробуйте увеличить буфер |

**Как читать:**

- падает скорость, растёт подгрузка → **не хватает сети** (или источник отдаёт медленно);
- растут потерянные кадры → **не хватает мощности компьютера**;
- картинка дёрнулась, а показатели ровные → часто виноваты метки времени в самом потоке (актуально для «народных» ретрансляций), а не сеть и не компьютер.

Скорость считается по приросту счётчиков LibVLC. Для адаптивных потоков (HLS) берётся больший из двух счётчиков, потому что сегменты могут скачиваться в обход счётчика входа.

## 🔁 Автопереподключение

Работает при ошибке открытия потока, при конце трансляции и при «замерзании» эфира.

| Ситуация | Реакция |
|---|---|
| Ошибка или конец потока | Переподключение |
| VLC «завис» на последнем кадре или бесконечно буферизует (нет пульса > 15 с) | Переподключение |
| Первая попытка | Немедленно |
| Дальнейшие попытки | Паузы 3 → 6 → 12 → 15 с |
| Максимум попыток | 5 подряд |
| Сброс счётчика | После 30 с стабильного эфира или при любом ручном действии |
| Пауза пользователя | **Не считается** зависанием |

Любое новое воспроизведение (выбор другого канала, «Стоп») отменяет запланированное переподключение. Отключить можно в настройках.

## ✅ Проверка доступности каналов (не работает корректно!!!)

**Настройки → Проверка каналов** (режим «Профи»).

Программа обходит плейлист и **приглушает** каналы, которые сейчас точно не отвечают. Канал остаётся в списке: он просто выглядит бледнее и получает пометку «— недоступен».

**Принципы:**

- Проверяются только `http://` и `https://`. Для `udp`, `rtsp`, `rtp` дешёвой проверки нет, такие каналы **не помечаются**.
- Отправляется короткий `GET` с `Range: bytes=0-2048` и заголовками канала (`User-Agent`, `Referer` из `#EXTVLCOPT`).
- Успешный ответ (коды 2xx–3xx) → канал жив.
- **404, 410, 451** → канал недоступен.
- Всё остальное (таймаут, 401/403, ошибки TLS, 5xx) → **«не подтверждено»**. Ложные красные метки не ставятся: такой поток часто спокойно открывается в VLC с нужными параметрами.
- Отметки не сохраняются между запусками.

> ⚠️ У многих платных провайдеров есть ограничение числа одновременных подключений на аккаунт. Массовая проверка создаёт несколько параллельных запросов и в редких случаях может «выбить» ваш текущий просмотр.

## 📱 Пульт с телефона

Встроенный веб-сервер позволяет управлять плеером с телефона или планшета в **той же домашней сети (Wi-Fi)**. Видео на телефон не передаётся: это именно пульт со списком каналов и кнопками.

### Включение

1. **Настройки → «Включить пульт»**.
2. Программа покажет адрес вида `http://192.168.1.25:8090` и **код доступа** (4 цифры).
3. Откройте этот адрес в браузере телефона и введите код.
4. Если телефон не подключается, нажмите **«Разрешить пульт в брандмауэре Windows»**. Программа добавит узкое правило только для себя, порта пульта и частной сети (Windows запросит подтверждение UAC).

### Что умеет пульт

- Список каналов с поиском, вкладки «Все / Избранное / Недавние».
- Выбор канала касанием, добавление в избранное звёздочкой.
- Кнопки «Назад» / «Пауза» / «Вперёд», громкость, «Звук».
- Показывает, что сейчас играет; состояние обновляется каждые 2 секунды.
- Введённый код запоминается в браузере телефона.

### Кнопки в настройках

- **Новый код** — сгенерировать другой PIN.
- **Обновить адрес** — заново определить IP-адрес компьютера (например, после смены сети).

### HTTP API

Страница пульта общается с программой по простому JSON API. Все запросы к `/api/*` требуют параметра `pin`.

| Метод | Путь | Тело | Описание |
|---|---|---|---|
| GET | `/` | — | HTML-страница пульта |
| GET | `/api/state` | — | Текущее состояние (канал, пауза, громкость…) |
| GET | `/api/channels?tab=all\|fav\|history&q=…` | — | Список каналов |
| POST | `/api/play` | `{"number": 5}` | Включить канал |
| POST | `/api/next` / `/api/prev` | — | Следующий / предыдущий канал |
| POST | `/api/playpause` | — | Пауза / продолжить |
| POST | `/api/volume` | `{"value": 60}` | Громкость 0–100 |
| POST | `/api/mute` | — | Переключить звук |
| POST | `/api/favorite` | `{"number": 5}` | Переключить избранное |

Пример: `http://192.168.1.25:8090/api/state?pin=1234`

### Безопасность пульта

Пульт рассчитан на **доверенную домашнюю сеть**. Пожалуйста, учитывайте:

- Соединение идёт по обычному **HTTP без шифрования**, PIN передаётся в адресе запроса.
- Код состоит из 4 цифр. Пульт управляет только плеером (не файлами компьютера), но не включайте его в общественных или недоверенных сетях.
- Сервер слушает все сетевые интерфейсы, поэтому правило брандмауэра создаётся только для **частной** сети.
- Не пробрасывайте порт пульта в интернет.
- PIN и содержимое запросов **не попадают** в журнал `remote_server.log`.

### Технические детали

Сервер написан на «голом» `TcpListener`, а не на `HttpListener`: последний на Windows 7 требует прав администратора или ручной регистрации адреса через `netsh`, а `TcpListener` работает от обычного пользователя без настройки. Файл журнала `remote_server.log` автоматически ротируется при достижении 256 КБ.

## 🗂 Где программа хранит данные

Все файлы лежат **рядом с `iptv.exe`**, поэтому программа переносима: скопировали папку — перенесли и настройки.

| Файл | Содержимое |
|---|---|

**Избранное и история** привязаны к адресу потока. Если вы меняете адрес канала, программа переносит отметку избранного на новый адрес.

### Модель потоков

Главная идея: **поток интерфейса не должен ждать LibVLC**. Любое обращение к нативному плееру может подвиснуть на мёртвом сетевом сокете, а вместе с ним замерло бы и окно.

```
UI-поток ──RequestPlay()──▶ PlayRequest ──▶ [_pendingRequest] ──signal──▶ Рабочий поток
   ▲                                       (хранится только последняя)      │
   │                                                                          ├─ Stop() (блокирующий)
   │◀────────── события LibVLC (Playing/Buffering/Error…) ─── libvlc ◀───────┤
   │              кэшируются в CachedState                                    └─ Play()
   │
   └─ Таймер 500 мс читает ТОЛЬКО кэш и объясняет пользователю, что происходит
```

- **Схлопывание заявок.** При быстром переключении в очереди хранится только последний запрос. Пока рабочий поток останавливал старый канал, мог прийти новый, и тогда устаревший запуск пропускается.
- **Явная остановка перед запуском.** Иначе `Play()` неявно ждал смерти старого сетевого потока в момент запуска нового.
- **Кэш состояния.** Свойства `MediaPlayer` берут внутренний мьютекс, поэтому интерфейс читает `CachedState`, обновляемый из событий LibVLC (`Interlocked`).
- **Громкость и формат кадра.** Тоже уходят в фон, порядковый номер отсекает устаревшие значения при быстром вращении колеса.
- **Общий замок `_vlcLock`.** `Stop`/`Play`, освобождение `Media` и чтение статистики не пересекаются между потоками.
- **Завершение.** Освобождение LibVLC выполняется в отдельном фоновом потоке, чтобы процесс не завис в диспетчере задач из-за мёртвого сокета.

### Сторож замершего эфира

VLC при пропавшей сети часто не сообщает об ошибке: он бесконечно показывает последний кадр или «буферизует». Поэтому программа отслеживает **пульс**: тики времени (`TimeChanged`) и изменение процента буфера. Если пульса нет дольше 15 секунд (и раньше он был), запускается автопереподключение. Пауза пользователя сюда не попадает.

### Загрузка плейлиста

Чтение файла, декодирование и разбор выполняются в фоне. У каждой загрузки есть «поколение»: если пока шла загрузка вы запросили другую, результат первой отбрасывается. Коллекция каналов подменяется целиком одной операцией, а не `Clear` + `Add` по одному: на десятках тысяч каналов это разница в секунды.

### Пульт и UI-поток

Обработчик API вызывается из потока HTTP-сервера, а всё, что трогает элементы окна или коллекцию каналов, выполняется через `Dispatcher.Invoke`. Это чуть дороже прямого вызова, зато исключает гонки без отдельной синхронизации.

## ❓ FAQ и решение проблем

### Программа не запускается вообще

1. Вы скопировали **только** `iptv.exe`? Нужна вся папка (DLL и `libvlc`).
2. Разрядность не совпадает: сборка x64 не запустится на 32-битной Windows. Соберите под **x86**.
3. Не установлен подходящий **.NET Framework**. Поставьте 4.8 (на Windows 7 сначала SP1).
4. Файлы пришли из интернета или мессенджера и заблокированы Windows: ПКМ на DLL → «Свойства» → «Разблокировать».
5. Посмотрите причину: **Панель управления → Администрирование → Просмотр событий → Журналы Windows → Приложение**. Ищите красную запись «.NET Runtime» или «Application Error».

### «Не удалось найти библиотеки VLC»

Рядом с программой должна лежать папка `libvlc` (с `libvlc.dll` и `plugins`) той же разрядности, что и приложение.

### Чёрный экран, звук есть

Откройте **Настройки → Аппаратное декодирование**, выберите «Выключено» и перезапустите программу.

### Картинка рассыпается, артефакты

Тот же совет: отключите аппаратное декодирование или попробуйте «DXVA2».

### Картинка дёргается, «кадров потеряно» растёт

Не хватает мощности. Включите режим питания «Высокая производительность», смените режим декодирования, выберите поток попроще (720p H.264), закройте другие тяжёлые программы, проверьте, не перегревается ли ноутбук.

### Картинка дёргается, а «кадров потеряно» = 0

Смотрите на скорость и буфер. Если они падают, виновата сеть или источник. Проверьте:

- **Wi-Fi.** Подключите кабель и сравните.
- **Источник.** Откройте тот же адрес в обычном VLC. Если там тоже дёргается, проблема в источнике, а не в этой программе. У бесплатных и «народных» плейлистов такое бывает часто: перегруженные серверы, цепочки перепередач, кривые метки времени в потоке.
- Увеличьте **буфер** до 1500–2500 мс.

### «Сервер не отвечает» / «Канал не открылся за 14 секунд»

Источник недоступен или блокирует запрос. Попробуйте:

- другой канал или другой плейлист;
- `Проверку каналов` (в режиме «Профи»), чтобы увидеть, какие каналы отвечают;
- убедиться, что в плейлисте есть нужные `#EXTVLCOPT` (часть каналов требует определённый `User-Agent` или `Referer`).

### Плейлист по `https` не скачивается на Windows 7

Программа включает TLS 1.2 для .NET, но сама Windows 7 должна его поддерживать. Установите все обновления Windows 7 SP1 и убедитесь, что установлен .NET Framework 4.8. Если ссылка по-прежнему не открывается, скачайте плейлист браузером и загрузите как файл.

### В плейлисте русские названия превратились в «кракозябры»

Кодировка определяется автоматически (UTF-8 → Windows-1251). Если и это не помогло, пересохраните файл в UTF-8 в любом текстовом редакторе.

### Телефон не подключается к пульту

- Телефон и компьютер должны быть в **одной Wi-Fi-сети**.
- Нажмите «Разрешить пульт в брандмауэре Windows» и подтвердите запрос.
- Нажмите «Обновить адрес»: у компьютера мог смениться IP-адрес.
- Порт `8090` может быть занят другой программой. Тогда пульт сообщит об ошибке запуска.
- В сети с изоляцией клиентов (гостевой Wi-Fi, некоторые роутеры) устройства не видят друг друга.
- Загляните в `remote_server.log`: там видны попытки подключения.

### Пропали мои правки плейлиста

Рабочий плейлист хранится в `user_playlist.m3u` рядом с exe. Если программа установлена в защищённую папку, запись могла не пройти. Используйте установщик или портативную папку вне `Program Files`.

### Можно ли смотреть архив передач и телепрограмму?

Пока нет. Ссылка на EPG и теги `catchup` считываются и сохраняются, но не используются. См. [планы развития](#-планы-развития).

### Работает ли программа на Windows 10/11?

Да, LibVLC 3.x и WPF поддерживают современные версии Windows. Проект целенаправленно оптимизирован под Windows 7 и слабое железо, но не ограничен ими.

### Откуда взять плейлист?

Из тех источников, которыми вы вправе пользоваться: плейлист вашего провайдера, ваша платная подписка, официальные открытые потоки вещателей. Программа не предоставляет каналов.

- модель процессора и видеокарты;
- что показывает **индикатор потока** в момент проблемы (скриншот);
- пример строки плейлиста для проблемного канала (**без логинов и паролей!**);

## 🌍 English summary

**IPTV Player (Win7 Edition)** is a lightweight IPTV player for Windows built on WPF and LibVLC 3.x. It is designed around two goals: to be **dead simple for non-technical, older users**, and to **run well on weak Windows 7 laptops with unstable internet**.

**Highlights**

- Plays anything LibVLC supports (HTTP/HLS, UDP, RTSP, …); loads M3U/M3U8 from a file or URL with automatic encoding detection (UTF-8/UTF-16/Windows-1251), `#EXTVLCOPT`, `#EXTHTTP` and `url|User-Agent=…` support.
- TV-style controls: number entry, previous-channel recall, favorites (click the star), recents, multi-word search, categories.
- "Simple" and "Expert" UI modes; three text sizes.
- All blocking LibVLC calls run off the UI thread; play requests are coalesced; player state is cached from events.
- Auto-reconnect with growing delays and a stall watchdog for frozen streams.
- Live stream diagnostics overlay: download speed, dropped frames, buffer state.
- Bulk channel availability checker that only flags unambiguous "not found" answers (404/410/451).
- Phone remote control over your home network (TcpListener-based HTTP server, PIN-protected, no admin rights needed).
- Atomic file writes; settings and playlist are stored next to the executable (portable).

**Requirements:** Windows 7 SP1+, .NET Framework 4.7.2 (4.8 recommended). Build with Visual Studio; target **x86** for the widest compatibility.
